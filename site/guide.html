01 · 설계 목적

필요한 만큼 찾고,
내 컴퓨터에서 관리합니다.

에이전트는 Hub 하나를 연결점으로 사용합니다. 먼저 스킬·등록 서버·연결된 도구를 검색하고, 선택한 항목의 지침이나 schema를 읽은 뒤 사용합니다. 모든 지침과 도구 설명을 매번 한꺼번에 읽는 방식은 아닙니다.

작업 지침은 재사용
공용·개인·프로젝트 출처를 나누고, 필요한 카테고리만 선택합니다.
외부 연결은 직접 선택
등록·로그인·호출 승인을 구분합니다. 검색했다는 이유만으로 외부 명령을 실행하지 않습니다.
상세는 확인할 때
일반 도구는 검색 후 호출하며, Apps·Tasks 도구의 직접 노출은 지원 조건에 따릅니다.

03 · MCP

어떤 도구를
연결할 수 있나요?

MCP는 에이전트가 도구·리소스·prompt를 이용하는 연결 규격입니다. 아래는 제품의 제공 범위이며, 내 컴퓨터의 현재 연결 목록은 아닙니다.

처음 설치하면 Hub가 연결됩니다. 외부 MCP 서버는 자동 등록되지 않습니다. 사용할 서버를 선택해 준비하고 등록·인증해야 합니다.

Joongi Hub MCP기본 설치joongi-hub
스킬·연결 도구 검색, 상세 조회·호출, 연결·인증·승인·관리 화면을 제공합니다. 기본은 stdio이며 HTTP는 선택합니다.
Python 코드 그래프동봉 · 직접 등록joongi_hub.code_graph
Python AST에서 심볼·호출 관계·영향 범위를 읽기 전용으로 분석합니다. 분석할 프로젝트 경로를 지정합니다.
Code Review Graph외부 패키지 · 선택 설치code-review-graph
여러 언어의 코드 그래프를 조회하는 외부 MCP입니다. 프로젝트마다 인덱스를 분리하는 연결 방식을 안내합니다.
격리 Playwright 브라우저Docker · 선택 설치Playwright MCP
별도 Chromium에서 화면 확인·클릭·입력에 사용합니다. Linux/WSL·Docker와 허용 사이트 설정이 필요합니다.
기존 Windows Edge확장·로컬 bridge · 선택 설정Personal Edge
사용자가 승인한 전용 탭에서 기존 로그인 상태를 활용합니다. 격리 브라우저와 다른 권한 경계이며 OS 샌드박스가 아닙니다.
직접 등록하는 외부 MCP제공자별 준비·인증
Notion 같은 원격 서비스나 로컬 MCP를 등록합니다. 실제 MCP 주소·전송 방식·서버와 클라이언트의 지원 기능을 확인해야 합니다.

Apps·Tasks·프로토콜 지원 범위 · 로그인과 호출 승인

검증한 도구와 추가 후보는 어디서 보나요?

GitNexus의 과거 실접속 기록과 Serena 등의 추가 후보는 코드 그래프 검증 기록에 있습니다. 날짜가 있는 시험은 현재 설치·연결 상태나 모든 버전의 호환성을 보장하지 않습니다.

04 · Prompts

재사용할 요청을
불러오는 별도 방식.

MCP prompt는 인자를 받아 대화 메시지를 구성하는 템플릿입니다. 작업 방법을 담은 스킬, 실행하는 tool과 역할이 다릅니다.

현재 함께 배포하는 공용 prompt 번들은 없습니다. Prompts를 지원하는 MCP 서버를 연결하면, 그 서버의 prompt 목록과 내용을 중계할 수 있습니다.

사용 가능 여부는 연결된 서버와 에이전트의 prompts 지원에 달려 있습니다. Hub의 스킬·도구 검색 결과에 prompt가 함께 나온다는 뜻은 아닙니다.

지원하는 MCP 요청 확인

prompts/list에서 연결 서버의 목록을 받고 prompts/get으로 내용을 요청합니다. 이름은 서버ID__prompt이름으로 출처를 구분합니다. 공용 prompt 생성·편집 화면을 제공하는 기능과는 구분합니다.
