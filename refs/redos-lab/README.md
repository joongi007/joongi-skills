# ReDoS 실측 — 파국적 백트래킹 재현

`web-security.md` §3.8 / PLAYBOOK §24 의 근거 자료.

**주장**: 파이썬 `re`는 백트래킹 엔진이고 타임아웃이 없어서, `(a+)+$` 같은 중첩 수량자에
매칭 실패하는 입력을 주면 입력 한 글자마다 소요 시간이 **두 배**가 된다.

**확인 방법**: 표준 라이브러리만 쓴다. 설치할 것 없음.

```bash
python3 measure_backtracking.py        # 20~28자, 약 10초
python3 measure_backtracking.py 31     # 20~31자, 약 80초
```

## 실측 결과

측정 환경: Python 3.10.12 / WSL2 (Linux 6.18) / 2026-09-05.
절대 시간은 기기마다 다르지만 **두 배씩 늘어나는 형태**는 동일하다.

| 입력 길이 | 소요 |
|---|---|
| 20 | 0.02초 |
| 24 | 0.31초 |
| 26 | 1.30초 |
| 28 | 4.97초 |
| 30 | 19.98초 |
| 31 | 40.37초 |

입력 `"a" * n + "!"` — 마지막 `!` 때문에 매칭이 **실패**하고, 그 실패를 확정하려고
엔진이 모든 분할 조합을 시도한다. 31자짜리 문자열 하나가 코어 하나를 40초 점유한다.
동시 요청 몇 개면 워커가 전부 묶인다.

## 여기서 나오는 규칙

1. **정규식 실행 전에 길이를 자른다.** `if len(s) > 256: reject` — 가장 싸고 효과적이다.
   위 표에서 보듯 길이가 곧 지수의 밑이다.
2. **중첩 수량자를 리뷰에서 잡는다**: `(x+)+`, `(x|x)*`, `(.*a){10}`.
3. 사용자가 정규식 자체를 입력하는 기능이면 `google-re2`(백트래킹 없는 유한오토마타).
4. Pydantic v2는 기본 엔진이 Rust regex(선형시간)라 안전하다.
   **`regex_engine="python-re"`로 바꾸면 이 취약점이 되살아난다.**
