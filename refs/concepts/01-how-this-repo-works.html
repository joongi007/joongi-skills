규약을 문서가 아니라 동작으로 만든다

플레이북을 문서로만 두면 아무도 안 읽는다. 스킬로 만들면 에이전트가 코드를 쓰기 전에 읽는다. 이 저장소가 하는 일은 그 변환을 반복 가능하게 만드는 것이다.

편집

소스 한 벌

skills/ 아래 markdown이 유일한 원본이다. --link 로 ~/.claude/skills 에 심볼릭 링크를 걸어두면 고치는 즉시 반영된다. 빌드를 기다릴 필요가 없다.

검증

어긋나면 알려준다

frontmatter 규칙, 500줄 한도, 목차 누락, 라우팅 표에서 빠진 참조 파일을 --check 가 잡는다. 규칙을 문서에만 적어두면 반드시 어긋난다.

이식

Claude 밖에서도

.skill 번들은 배포용, AGENTS.md 는 Codex·Cursor·Zed 용 진입점. 지침 본문은 한 곳에만 있고 나머지는 포인터라 사본이 갈라지지 않는다.

핵심 메커니즘

세 단계로 나눠 읽힌다

스킬이 길어도 되는 이유가 여기 있다. 전부가 한꺼번에 로드되지 않는다. 각 단계는 앞 단계가 통과했을 때만 열린다.

01
항상 — 모든 세션 시작 시

description 964자

스킬 이름과 description만 미리 로드된다. 이 한 문단이 "이 작업에 이 스킬을 쓸까"를 혼자 결정한다. 그래서 트리거 단어(FastAPI, JWT, Docker, PR 리뷰, 디버깅…)를 최대한 눌러 담았다.

대략 240 토큰. 저장소 전체에서 무조건 비용이 발생하는 부분은 여기뿐이다.

02
관련 있다고 판단됐을 때

SKILL.md 본문 120줄

목차 역할. 언제 적용되는지, 기본값이 무엇인지, 그리고 라우팅 표 — "작업이 X를 건드리면 references/y.md 를 읽어라"가 14줄.

매번 필요한 짧은 규칙(보안 4원칙, 우선순위)은 참조 파일에 두지 않고 여기 인라인했다.

03
라우팅 표가 지목했을 때만

참조 파일 — 해당하는 것만

FastAPI 엔드포인트를 쓰면 python-api.md 233줄이 열린다. web-security.md 794줄은 인증·권한·사용자 입력·업로드를 건드릴 때만 열린다.

변수명 하나 바꾸는 작업에서는 2,566줄 중 한 줄도 읽히지 않는다.

빌드

build.sh 하나로 끝난다

bash + coreutils만 쓴다. zip 압축은 zip 이 있으면 그걸, 없으면 python3 의 zipfile로 폴백한다.

명령하는 일
./build.sh검증 후 dist/*.skill 로 패키징
--check검증만. 커밋 전·CI용
--link~/.claude/skills 에 심볼릭 링크 — 편집이 즉시 반영
--agentsAGENTS.md 재생성
--cleandist/ 삭제

검증은 frontmatter(이름·설명·한도)뿐 아니라 작성 규칙이 어긋났는지도 본다. 규칙을 문서에만 적어두면 반드시 어긋나기 때문에, 세 가지를 경고로 만들었다. 

$ ./build.sh --check
ok   engineering-playbook             16 files
warn lint-me   SKILL.md body is 505 lines (guideline: under 500)
warn lint-me   references/orphan.md is 151 lines with no table of contents
warn lint-me   references/orphan.md is never mentioned in SKILL.md — it will not be discovered

세 번째가 특히 중요하다. 라우팅 표에 없는 참조 파일은 존재하지만 절대 읽히지 않는다. 조용히 죽어 있는 파일을 만들지 않으려는 검사다.

refs/

규칙에는 근거가 있어야 한다

"권한 검사부터 봐라" 같은 규칙은 어딘가에서 나왔다. 그 출처가 사라지면 규칙은 미신이 된다. refs/ 가 그 자리고, 세 종류를 섞지 않는다.

A · 참고 자료

주제 폴더 + 최소 예제

구현할 때 꺼내 보는 코드. README.md 에 무엇인지·출처·언제 쓰는지, 그리고 실제로 돌려볼 수 있는 파일.

B · concepts

개념 시각 설명 (HTML)

눈으로 보게 만든 문서. NN- 순번을 붙인다. 이 문서가 01 이다.

C · research

조사 종합 노트

외부 문서·표준·논문을 읽고 정리한 것. 파일명은 YYYY-MM-DD-주제.md. 출처 URL과 조회 날짜를 반드시 남긴다.

  • 출처와 조회 날짜를 적는다. 원문이 바뀌면 요약은 틀린 게 된다.
  • 원문이 아니라 요약이면 밝힌다. 인용과 우리 해석을 섞지 않는다.
  • 측정값에는 측정 환경을 붙인다. 숫자만 있으면 재현이 안 된다.
  • 양방향으로 연결한다. 스킬은 근거를 가리키고, 자료는 어디에 반영됐는지 적는다.
  • INDEX 표에 없으면 없는 자료다. 추가하면 한 줄 추가한다.

실제로 이 규칙이 한 번 작동했다. 플레이북이 근거로 든 "OWASP API Top 10에서 인젝션은 8위"를 확인하러 갔더니, 2019년판 기준이었고 2023년판에는 인젝션 항목이 아예 없었다. 대신 권한이 API1·API3·API5 세 자리를 차지한다 — 원래 주장(권한부터 보라)은 오히려 강해졌다. 조사 노트를 남기고 플레이북 문장을 고쳤다.

최근 변경

보안 체크리스트 편입

웹 백엔드 보안 문서를 플레이북 §24로 넣으면서, 읽히기만 하는 게 아니라 실제로 수행되도록 연결했다.

연결한 곳무엇을
descriptionIDOR·인젝션·SSRF·업로드·race condition 트리거 단어 추가
SKILL.md 본문핵심 4원칙과 우선순위를 인라인 — 매번 필요하므로 참조 파일에 두지 않음
라우팅 표2줄 추가. 표에 없으면 읽히지 않는다
리뷰 절차보안 패스를 5단계로 삽입. 보안 발견을 스타일보다 먼저 보고
checklist.md어떤 변경이든 걸리면 멈추는 11개 항목
refs/ReDoS 실측(31자 = 40초), ASGI 바디 제한 최소 구현, OWASP 대조

한 가지 미해결: 보안 문서는 토큰을 localStorage 에 두지 말라고 하는데, 기존 규약(§20.2)은 refresh token을 거기 둔다. 충돌을 문서에 명시해두고 어느 쪽을 택할지는 남겨뒀다 — 임의로 한쪽을 지우지 않았다.

다음

새 스킬을 넣으려면

skills/<kebab-case-이름>/SKILL.md 를 만들고 frontmatter에 name(디렉터리 이름과 같아야 한다)과 description 을 채운다. 내용이 길어지면 references/ 로 빼고 라우팅 표에 한 줄 추가한다.

그리고 ./build.sh --check. 나머지는 스크립트가 잡아준다.
