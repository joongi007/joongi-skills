# 처음 사용하기

Joongi Skills & Hub를 처음 설치하는 사람을 위한 안내입니다. 별도 대화나 개발자의 컴퓨터 설정을 알 필요는 없습니다.
이미 설치했다면 2단계부터 시작하세요. [설치 상세](../installation/00-index.md).

## 1. 환경을 준비하고 설치하기

- 사용할 AI 에이전트가 있어야 합니다. 설치기는 에이전트 설정 폴더를 감지하며 앱을 설치하지는 않습니다.
- Python 3.10 이상을 준비합니다. 다운로드 설치·업데이트에는 `gh attestation verify`를 지원하는 GitHub CLI도 필요합니다.
- Windows 앱에서 쓸 것인지 WSL 안의 에이전트에서 쓸 것인지 정하고 그 환경의 명령으로 설치합니다.
  Windows와 WSL은 기본 홈·설정·상태가 다릅니다. [WSL 연결 선택](../installation/00-index.md#wsl에서-사용하기).

[설치 페이지](https://joongi007.github.io/joongi-skills/#install)에서 OS별 짧은 명령을 복사합니다.
다운로드한 최초 스크립트도 실행 전에 검증하려면 [보안 설치](../installation/04-verified-install.md)를 선택합니다.
권한·검증 오류가 있으면 검증을 끄거나 관리자 권한으로 재실행하지 말고 [설치 문제 해결](../installation/00-index.md#설치가-안-될-때)을 확인하세요.

## 2. 에이전트에서 연결 확인하기

설치가 끝나면 에이전트의 MCP 설정에서 `joongi-hub` 연결을 다시 엽니다.
MCP 재연결 기능이 없다면 새 에이전트 세션을 엽니다. 다음과 같이 요청합니다.

> Hub에서 usual-korean 스킬을 찾아 읽어줘.

스킬을 찾고 지침을 읽을 수 있으면 기본 연결을 확인한 것입니다.
검색 기본값은 한 줄 요약 5개이며, 상세에서 설명과 schema를 확인한 뒤 읽거나 실행합니다.
필요 없는 기본 스킬이나 회사 출처는 관리 화면의 [검색 설정](../operations/14-catalog-preferences.md)에서 선택합니다.
이미 에이전트 폴더에 설치된 스킬은 별도이므로 native 설치를 줄이려면 [설치의 카테고리 제외](../installation/00-index.md#클론에서-설치)도 확인하세요.
외부 MCP 서버 목록이 비어 있어도 정상입니다. 서비스 로그인이나 외부 도구 호출은 아직 하지 않은 상태입니다.
새 native 스킬 목록은 에이전트가 세션을 다시 열어야 갱신될 수 있습니다.

## 3. 웹 화면이 필요할 때 열기

> Hub 설정 화면 열어줘.

에이전트가 지원하는 `hub_open_settings`로 임시 관리 화면을 엽니다.
창을 닫으면 임시 웹이 정리됩니다. 계속 관리할 웹을 직접 열려면 다음 명령을 씁니다.

```bash
~/.local/bin/joongi-hub open
```

Windows PowerShell에서는 다음과 같습니다.

```powershell
& "$HOME/.local/bin/joongi-hub.cmd" open
```

이 명령은 필요하면 웹 서버를 시작합니다. 브라우저 탭을 닫는 것만으로 상시 웹이 중지되지는 않습니다.
종료하려면 같은 경로의 `joongi-hub stop`을 사용합니다. [연결 방식과 웹 수명](../operations/06-connection-modes.md).
기본 stdio 연결은 에이전트가 Hub를 실행하므로 웹을 미리 켤 필요가 없습니다.

## 4. 외부 MCP 등록·연결·로그인하기

1. 관리 화면의 **MCP 연결 → + MCP 등록**에서 사용할 서버의 설정을 입력합니다.
2. 원격 서버는 제공자의 실제 MCP 주소를, 로컬 서버는 설치된 실행 파일·인자·허용 경로를 입력합니다.
   GitHub 저장소 URL은 MCP 서버 주소가 아닙니다. 로컬 실행에는 [격리 환경](../operations/10-security-boundaries.md)이 필요합니다.
3. **연결 확인**으로 도구 목록을 가져옵니다. 등록만으로 연결 성공이나 인증 완료를 뜻하지 않습니다.
4. 로그인이 필요하면 서버의 **인증** 설정을 저장하고 로그인합니다. 예를 들어 `notion`이라는 ID로 등록했다면
   에이전트에게 “notion 로그인을 시작해줘”라고 요청할 수도 있습니다.
5. 사용자가 서비스의 접근 권한을 직접 승인합니다. 비밀번호·토큰을 채팅에 붙여넣지 않습니다.

인증한 도구를 처음 실행하면 호출 승인을 요청할 수 있습니다. 대상·도구·인수를 확인하고
이번 호출·1시간·항상 허용 중 필요한 범위를 선택합니다. OAuth 로그인 동의와 Hub의 호출 승인은 별개입니다.
[인증·승인 상세](../operations/05-auth-project-skills.md).

## 알아두면 편한 용어

| 용어 | 이 제품에서의 의미 |
|---|---|
| 스킬 | 에이전트가 읽는 Markdown 작업 지침. 실행 도구 자체는 아님 |
| MCP 서버 | 에이전트에게 도구·리소스 등을 제공하는 로컬 프로그램 또는 원격 서비스 |
| Hub | 에이전트와 여러 MCP 사이에서 연결·검색·호출을 관리하는 로컬 프로그램 |
| stdio | 에이전트가 자식 프로세스로 Hub를 실행해 표준 입출력으로 통신하는 기본 방식 |
| HTTP | 별도로 실행 중인 Hub 서버에 연결하는 방식 |
| 공용·프로젝트 범위 | Hub 안에서 사용할 연결·스킬·인증을 선택하는 단위. OS 사용자 격리는 아님 |
| 등록·연결·인증 | 설정 저장, 실제 서버 접속, 서비스 권한 획득의 서로 다른 단계 |
