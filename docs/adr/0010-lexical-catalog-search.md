# ADR-0010: 임베딩보다 메타데이터 어휘 검색을 먼저 개선

상태: accepted · 날짜: 2026-11-11

## 맥락

기존 `hub_search`는 이름·설명의 부분 문자열 일치 개수만 계산했다. 정확한 도구 이름보다
그 이름을 예로 든 설명이 먼저 나오고, 인자 이름이나 CamelCase 분리 검색은 빠졌다.
사용자는 grep과 유사한 검색과 에이전트에 검색 방법을 안내하는 설명을 제안했다.

## 결정

이름·서버·설명·인자 메타데이터에 가중치와 단어 희소성을 적용한다. 정확한 이름을 우선한다.
고정 문자열 모드, 선택적 ripgrep 정규식, 필터·요약·결과 수 제한을 추가한다.
기존 결과 목록·기본 full·최대 100개와 native MCP/Apps 노출은 유지한다.
코드 그래프의 도구 설명은 각 도구의 실제 목적을 드러내도록 바꾼다.

## 대안과 결과

임베딩은 도메인별 표현·언어가 다른 의미 검색에 유리할 수 있지만 모델·색인 갱신·배포가
추가된다. 현재는 정확한 식별자와 검색어 재작성으로 해결되는 문제를 먼저 다룬다.
의미가 같은 다언어 질의의 누락이 실제 사용에서 반복되면 동일한 평가셋으로 임베딩 또는
어휘+의미 하이브리드를 비교한다. 이번 구현은 교차 언어 의미 검색을 해결하지 않는다.

매번 메타데이터를 처리하므로 단순 부분 문자열보다 CPU 비용이 커졌다. 느린 검색이 실제로
관측되면 카탈로그 변경 시에만 갱신하는 메모리 색인을 검토한다. 클라이언트 자체 검색은
별도 계층이며 이 변경으로 모델 작업 성공률이 올랐다고 주장하지 않는다.
