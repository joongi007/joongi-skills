# ADR-0014: 설치 방식의 신뢰 차이와 처음 사용하는 사람의 안내

상태: accepted · 날짜: 2026-11-19

## 맥락

실행 전 bootstrap 검증을 위한 긴 명령이 기본 화면 전체를 차지해 처음 설치하기 어렵다.
대화에서 누적한 설명은 공개 문서의 독자가 알고 있다고 가정할 수 없다.
간편 설치와 서명 확인 설치를 같은 보안 보장으로 설명해서도 안 된다.

## 결정

기본 화면에는 OS별 짧은 HTTPS 다운로드 실행 명령을 제공한다.
펼침 메뉴와 별도 문서에는 기존의 bootstrap 서명·출처·main 커밋 검증 명령을 유지한다.
간편 설치는 최초 bootstrap을 HTTPS 배포 출처에 의존한다. 그 bootstrap이 archive의 서명을 검사한다.
보안 설치는 bootstrap도 실행 전에 검증한다. archive 검증·압축 해제 한도·소유권 보호를 생략하는 옵션은 만들지 않는다.

Bash 파이프 입력과 PowerShell inline scriptblock은 로컬 소스 파일 경로를 갖지 않는다.
이 경우 호출한 작업 폴더나 상위 스크립트의 경로에서 설치기를 찾지 않고 다운로드 경로를 사용한다.
실제 파일로 실행한 클론 설치만 해당 파일 옆의 로컬 설치기를 사용한다.

문서는 사용자용 첫 사용·설치·운영과 기여자용 설계·배포·검증 이력으로 구분한다.
과거 테스트 수·로컬 등록 목록은 날짜별 증거로 유지하고 새 설치의 기본 상태로 설명하지 않는다.

## 대안과 결과

짧은 명령은 최초 스크립트의 실행 전 독립 검증을 제공하지 않는다. 이 차이를 명령 옆에 알린다.
모든 검증을 끄는 빠른 설치, 의존성을 조용히 추가 설치하는 방식은 채택하지 않는다.
문서와 사이트는 준비 사항·OS·설치 후 행동을 함께 제공하고 복사·키보드·작은 화면을 검증한다.

## 검증

`tests/test_bootstrap_entrypoints.py`는 Bash 파이프·파일과 Windows inline scriptblock의 경로 선택을 검사한다.
`tests/browser_install.cjs`는 설치 경로 선택·명령 복사·키보드·반응형 화면을 검사한다.
기존 설치·서명 검증·문서 링크·호환성 계약 검사도 유지한다.
