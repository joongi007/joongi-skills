# ADR-0013 · 호스트 입력 채널을 통한 호출 승인

문서 ID: ADR-0013 · 상태: accepted · 작성일: 2026-11-18

## 맥락

GUI 에이전트 앱에서 호출을 선택하려고 매번 외부 브라우저를 여는 불편이 있다.
일반 MCP App에는 사용자와 모델이 함께 접근할 수 있는 도구·리소스만으로 승인 권한을
전달하면 모델의 자기 승인 경로가 생긴다. app visibility는 사용자 클릭 증명이 아니다.

## 결정

2025-11-25 stdio 호스트가 form elicitation을 협상했을 때만 서버 역방향 입력 요청을 보낸다.
무작위 request ID와 일치하는 호스트 응답만 받고, 명시적으로 체크된 현재 ID 목록을 기존
원자적 일회 승인 정책으로 처리한다. 현재 요청 승인 시 원래 요청을 그대로 한 번 재시도한다.
모델 호출 가능한 승인 도구·리소스에 비밀 capability를 추가하지 않는다.

한 폼은 최대 8개, 24 KB, 45초이며 대기 중 다른 입력은 최대 128개까지 보존한다.
거절·취소·잘못된 응답·기한 만료·변경된 승인 상태는 실행을 허용하지 않는다.
폼 미지원·2026·직접 HTTP·Tasks는 기존 브라우저 경계를 유지한다.
이 결정은 외부 서버의 일반 elicitation 프록시를 승인하지 않는다.

## 대안과 결과

범용 MCP `approve` 도구나 App-only visibility에 의존한 권한 부여는 채택하지 않는다.
Apps UI 내부 직접 승인은 신뢰할 수 있는 호스트별 사용자 증명 인터페이스가 있을 때 별도로 설계한다.
호스트 입력 채널도 악성 클라이언트와 동일 사용자 권한의 임의 코드를 격리하지는 못한다.

원래 브라우저 승인과 함께 동작하며 로그인·인증 정보는 호스트 폼에 전달하지 않는다.
검증과 사용 예시는 [운영 안내](../operations/12-3d-and-host-consent.md)를 따른다.
