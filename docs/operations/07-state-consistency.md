# 저장소 일관성과 복구

웹은 별도의 MCP 목록이 아니라 에이전트가 사용하는 등록 정보를 편집하는 화면이다.
stdio·hybrid·HTTP를 바꾸거나 웹을 꺼도 등록 정보가 바뀌지 않아야 한다.

## 실제 사용 경로

설치된 `joongi-hub` 런처는 설치한 사용자 홈의 `.local/share/joongi-hub`를 기본으로 고정한다.
작업 디렉터리나 상위 프로세스의 `JOONGI_HUB_STATE_DIR` 때문에 다른 목록을 읽지 않는다.
다른 저장소가 꼭 필요하면 모든 접점에 같은 `--state-dir`을 명시한다.
소스에서 직접 실행할 때는 `JOONGI_HUB_STATE_DIR` 또는 같은 사용자 홈 경로를 사용한다.
`JOONGI_HUB_INSTALL_STATE_DIR`는 설치기가 설정하는 내부 기본값이다.

```bash
joongi-hub state
joongi-hub open
joongi-hub stop
```

`state`, `status`, MCP 도구 `hub_status`는 실제 저장 경로·등록 수·백업 위치를 표시한다.
웹의 빈 목록도 현재 경로를 표시한다. 임시 저장소는 CLI stderr와 웹에 경고한다.
MCP stdout에는 JSON-RPC 이외의 진단 메시지를 쓰지 않는다.

Windows 네이티브와 WSL은 사용자 홈·실행 환경·인증 저장 방식이 서로 다르다.
따라서 각자 영구 저장소를 가진다. 같은 PC라는 이유로 파일을 자동 공유하지 않는다.
Windows 에이전트에서도 WSL 허브 하나를 쓰려면 연결 설정의 **Windows용 WSL 연결 생성**으로
WSL의 상태 경로가 고정된 연결을 사용한다. native Windows 런처는 Windows 저장소를 사용한다.

## 검토용 설정 가져오기

```bash
joongi-hub state --import-from /이전에/사용한/상태폴더
```

원본의 `servers.json`을 검증하고 대상에 없는 ID만 추가한다. 같은 ID의 다른 설정이 있으면
전체 가져오기를 중단한다. 원본을 지우거나 기존 등록을 덮어쓰지 않으며 서버를 실행하지 않는다.
임시 경로를 사용하는 실행 설정과 없는 절대 실행 파일은 거절한다. 먼저 영구 실행 환경을 만든다.
등록 파일이 이미 사라졌다면 빈 상태로 가져오지 않는다. 백업이나 기존 검증 기록에서 복구한다.

가져오기는 **MCP 서버 설정만** 다룬다. 인증 토큰·프로젝트·Tasks·색인 데이터의 이관은 아니다.
인증과 환경 변수는 대상 환경에서 다시 확인한다. 외부 MCP의 설치 환경도 자동으로 설치하지 않는다.

## 등록 파일 백업

추가·수정·삭제 후 마지막 등록 목록을 `backups/servers.json`에도 저장한다.
서로 다른 stdio·웹 프로세스의 변경은 OS 파일 잠금으로 직렬화한다.
등록 파일이 없어졌는데 백업이 남아 있으면 빈 목록으로 처리하지 않고 복구를 안내한다.

```bash
# servers.json이 없을 때만 실행한다. 기존 파일을 덮어쓰지 않는다.
joongi-hub state --restore-backup
```

마지막 서버를 의도적으로 삭제한 빈 목록도 백업하므로 삭제한 서버를 자동 부활시키지 않는다.
백업은 같은 저장소에 있는 마지막 목록 사본이다. 폴더 전체 삭제·디스크 고장·재해 복구용 백업을
대신하지 않는다. 등록 설정은 비공개 파일로 관리하고 외부 백업은 사용자의 백업 정책을 따른다.
