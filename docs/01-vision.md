# 제품 방향

문서 ID: DOC-VISION · 작성일: 2026-11-05

joongi-skills는 개발자의 규칙을 반복 설명하는 비용과 여러 MCP 연결을 관리하는 부담을
줄인다. 지식은 편집·검토 가능한 Markdown으로, 연결·실행은 로컬 Hub로 관리한다.

## 사용자와 사용 흐름

개인은 사용 중인 에이전트를 감지해 스킬과 Hub 연결을 설치한다. 다른 프로젝트에서도
같은 규칙을 사용하고 업데이트로 새 스킬과 새 에이전트 연결을 반영한다.
팀은 스킬 소스와 결정 근거를 검토하고 테스트 가능한 작업 단위로 기여한다.

1. 설치하거나 clone에서 실행한다.
2. 로컬 UI에서 스킬과 연결된 MCP를 확인한다.
3. 필요한 능력을 검색하고 선택한 지침·schema만 읽는다.
4. 도구를 호출하고 결과·진행 상태·실패 원인을 확인한다.
5. 업데이트·제거에서 개인의 다른 설정과 수정 파일을 보존한다.

## 성공 기준

- 의존성 설치 없이 지원 Python에서 clone을 바로 실행할 수 있다.
- 에이전트 설정은 한 Hub 접점을 사용하며, 도구 출처를 식별할 수 있다.
- 실제 지원 기능과 지원하지 않는 조합을 UI·문서에서 구분한다.
- 권한·출처·시간 예산을 유지하며 upstream 장애를 격리한다.
- 설치·업데이트·제거와 외부 계약은 재현 가능한 테스트로 확인한다.

## 제품 원칙

모든 스킬을 매 요청에 로드하지 않는다. 필요할 때 상세 내용을 읽는다.
스킬을 내려받았다는 이유만으로 명령을 자동 실행하지 않는다.
개인 로컬 사용을 기본으로 하며, 팀용 다중 사용자 서버는 별도 설계가 필요하다.
운영 기술과 디자인 패턴은 프로젝트 규모·복구 목표를 해결할 때 도입한다.

새 아이디어는 [작업 분할](development/01-work-packages.md)에 독립 수용 조건으로 추가한다.
