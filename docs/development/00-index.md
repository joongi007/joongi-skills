# 개발 절차

문서 ID: DEV-PROCESS · 요구사항: REQ-PROCESS

읽는 순서: [작업 단위](01-work-packages.md) → [테스트·문서 정합성](02-quality.md) →
[검증 기록](03-verification.md). 사람과 에이전트가 같은 작업서를 사용한다.

## 변경 흐름

1. 요구사항 ID와 외부 관찰 가능한 성공·실패를 정한다.
2. 영향을 받는 ADR·계약·소유 파일을 확인한다.
3. 독립 테스트로 검증 가능한 작업으로 나눈다. 계약과 fixture를 먼저 합의한다.
4. 겹치지 않는 소유 파일을 병렬 배정한다. 수정이 겹치면 담당자에게 변경을 요청한다.
5. 각 작업은 독립 테스트 결과와 제한을 인계한다.
6. 실제 구현끼리 연결해 버전·전송 조합과 전체 사용자 흐름을 검증한다.
7. 문서·상태표·운영 예제를 갱신하고 완료 증거를 남긴다.

## 작업 인계 형식

```text
작업 ID / 요구사항:
목적과 사용자 관찰 결과:
소유 파일:
선행 의존성:
입력·출력·오류·상태 계약:
정상·경계·실패 수용 테스트:
검증 명령과 필요한 환경:
결과·알려진 한계·다음 담당자:
```

독립 작업은 일감 크기보다 계약의 안정성과 파일 소유권으로 나눈다.
새 실패가 발견되면 fixture와 수용 테스트를 보강한 후 관련 작업에만 재검증을 요청한다.
사용자가 단일 에이전트를 원하면 같은 순서로 직렬 수행할 수 있다.
