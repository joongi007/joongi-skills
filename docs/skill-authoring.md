## 디렉터리 규약

```
skills/<skill-name>/
  SKILL.md          # frontmatter + 라우팅 인덱스. 500줄 미만
  <ORIGINAL>.md     # 원본 문서가 있으면 대문자 파일명으로 (예: PLAYBOOK.md)
  references/       # 주제별 참조 파일. SKILL.md에서 직접 링크
```

- 디렉터리 이름 = frontmatter `name` (빌드가 검증한다).
- 경로는 항상 슬래시. 백슬래시 금지.
- 파일명은 내용을 나타내게. `doc2.md` 금지, `web-security.md` 가 맞다.
- `refs/`(저장소 루트)는 스킬 **바깥**이다. 번들에 들어가지 않는다. 규약은 `refs/INDEX.md`.
- 스킬 본문에서 근거가 필요한 주장은 `refs/` 의 자료를 가리킨다 (경로만, 링크 아님 —
  참조 파일에서 스킬 밖으로 나가는 링크를 타게 만들지 않는다).

## SKILL.md 작성

- 본문 500줄 미만. 넘으면 `references/`로 뺀다.
- 구조: 목적 한 문단 → 사용 절차 → **라우팅 표** → 항상 필요한 기본값 → 작업 유형별 절차.
- **라우팅 표가 이 저장소 스킬의 중심이다.** "작업이 X를 건드리면 → `references/y.md`" 한 줄씩.
- 자주 쓰이는 짧은 규칙(3~10줄)은 참조 파일에 두지 말고 SKILL.md에 인라인한다.
  같은 파일을 매번 읽게 되면 그 내용은 SKILL.md에 있어야 한다는 신호다.
- description은 1,024자 제한을 실제로 센다. 트리거 키워드(프레임워크명, 파일 확장자,
  도메인 용어)를 최대한 넣되 한도를 넘기지 않는다.

## 참조 파일 작성

- **100줄이 넘으면 상단에 목차를 넣는다.** 예외 없음.
- 한 파일 = 한 도메인. 관련 없는 내용이 같이 로드되면 잘못 나눈 것이다.
- 원본 문서의 § 번호를 쓰면 **그 번호를 그대로 유지한다.** 사용자가 원문과 대조한다.
- 다른 참조 파일을 가리킬 때는 파일명 + § 를 함께 적는다 (`security-ops.md §10.2`).
  참조 파일끼리 링크를 타고 들어가게 만들지 않는다 — 한 단계 깊이 규칙.
- 코드 예시는 ❌/✅ 쌍으로. 설명 문단보다 대비되는 코드가 짧고 정확하다.

## 이식성 (Claude 외 도구)

### 작성 언어

이 개인 저장소에서는 **설명·지침·제목·표의 기본 언어를 한국어로 통일한다.**
기술명·명령어·경로·코드·식별자와 형식상 고정된 frontmatter 키는 원문을 유지한다.
외부 원문·직접 인용은 출처와 원문임을 구분하며 억지로 번역하지 않는다.

스킬 형식 자체가 한 언어만 지원하는 것은 아니며 지침의 언어와 결과의 출력 언어도 별개다.
여기서 한국어를 선택한 이유는 개인 자료를 일관되게 읽고 관리하기 위해서다.
언어를 바꿨다는 이유만으로 모델 성능이 좋아졌다고 주장하지 않는다.

전체 지침을 두 언어로 복제해 같은 컨텍스트에 넣지 않는다. 번역본이 필요하면
로딩 경로와 원본을 정해 중복·불일치를 막는다. 중요한 차이는 같은 모델과 작업 사례로 비교한다.
근거: `refs/research/2026-11-07-gtmux-ux-and-skill-language.md`.

### 화면 요약과 에이전트 지침

Hub 목록의 짧은 이름·요약은 사람이 탐색하기 위한 표현이다. 원래 description·schema·본문을
잘라 MCP에 제공하지 않는다. 전체 정보는 선택한 상세 화면과 원문에서 조회할 수 있어야 한다.
SKILL.md에는 핵심 판단과 routing을 두고, 긴 표·조건별 예시는 참조 파일로 옮긴다.

스킬 콘텐츠는 **순수 markdown**으로 유지한다. Claude 고유 기능에 의존하지 않는다.

- `./build.sh --agents` 가 `AGENTS.md`를 생성한다. Codex, Cursor, Zed 등
  AGENTS.md 규약을 읽는 도구가 스킬을 찾아갈 수 있게 하는 진입점이다.
- 따라서 SKILL.md의 라우팅 표는 **경로가 그대로 유효해야** 한다.
  상대 경로(`references/x.md`)만 쓰고, 스킬 디렉터리 밖을 가리키지 않는다.
- 도구별 전용 포맷(`.cursor/rules/*.mdc`, `.github/copilot-instructions.md`)은 만들지 않는다.
  필요해지면 그때 `build.sh`에 모드를 추가한다.

## 스킬을 고칠 때의 절차

1. `skills/` 아래 소스를 고친다 (`--link` 되어 있으면 즉시 반영된다).
2. `./build.sh --check` 로 frontmatter·구조를 검증한다.
3. 라우팅 표에 새 참조 파일 줄을 추가했는지 확인한다. **표에 없는 파일은 읽히지 않는다.**
4. SKILL.md 본문 줄 수를 확인한다 (`wc -l`). 500줄에 가까워지면 분할한다.
5. 실제 작업으로 테스트한다. 참조를 안 따라가면 링크가 눈에 덜 띄는 것이고,
   같은 파일만 반복해서 읽으면 그 내용을 SKILL.md로 올릴 때가 된 것이다.
