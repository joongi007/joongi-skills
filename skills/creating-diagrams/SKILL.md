# 다이어그램·기술 삽화와 아이콘

사용자의 설명 목적·편집 방식·출력 크기에 맞춰 도구를 선택한다.
diagram-design·anatomy의 접근을 참고해 작성한 독립 지침이며, 원본 스킬 전체나 MCP 서버를 설치한 것은 아니다.

## 진행

1. 전달할 관계·순서·상태 또는 아이콘의 의미와 독자·삽입 위치·목표 크기를 정리한다.
2. 다이어그램은 먼저 `references/design-principles.md`를 읽어 공통 기준을 적용한다.
   기존 디자인 토큰과 사용자가 지정한 형식을 우선하고 아래 표에서 필요한 형식별 참조만 더 읽는다.
3. 원본을 만들고 실제 목표 크기로 렌더한다. 관계의 정확성·읽는 순서·글자·연결선·대비·한글 폰트를 확인한다.
4. 대상 문서·앱에 맞게 SVG/PNG 또는 지원되는 원본을 삽입하고, 삽입된 크기로 다시 확인한다.
   편집 가능한 원본과 실제 렌더 산출물을 함께 제공한다. 기존 자동 빌드가 있으면 그 경로를 재사용한다.
   미실행은 미실행으로 표시한다.

| 작업 | 읽을 자료 |
|---|---|
| 모든 다이어그램의 설명·배치·연결선·검수 기준 | `references/design-principles.md` |
| Mermaid·Excalidraw·SVG/HTML 선택, 편집·렌더·내보내기 | `references/diagrams.md` |
| 등각투영·분해도·시스템 삽화, 앱·웹 아이콘 | `references/illustrations-icons.md` |
| DOM 화면·요소를 이미지로 캡처, snapdom·Playwright 선택 | `references/capture.md` |

## 공통 기준

- 도형·화살표·범례의 뜻과 실제 시스템을 맞춘다. 장식으로 순서·인과·축척을 오해하게 만들지 않는다.
- 관계만 필요한 Git 문서는 Mermaid를 우선 검토한다. 발표용 정밀 배치는 SVG/HTML,
  사람이 화이트보드에서 재편집하려면 Excalidraw가 적합하다. 파일 확장자만 바꿔 변환했다고 하지 않는다.
- 구조 설명에 입체감이 필요할 때만 anatomy식 등각투영을 선택한다. 모든 UI나 순서도를 입체화하지 않는다.
- 기존 디자인을 따르고 새 정책은 하나씩 채택한다. 특정 폰트·색·그림자 금지 같은 원본 취향은 강제하지 않는다.
- 공통 원칙은 Mermaid·Excalidraw·SVG·HTML 모두에 적용하되, 형식이 표현하지 못하는 기능을 지원한다고 하지 않는다.
- 비밀이 있는 문서·화면을 외부 편집기·렌더 서비스·갤러리에 자동 업로드하지 않는다.
- SVG/HTML·입력 이미지·출력 canvas에 바이트·치수·픽셀·시간·동시성 제한을 둔다.
  링크·script·외부 리소스를 가진 입력을 그대로 실행하지 않는다.
- 설치되어 있지 않은 도구를 사용했다고 말하지 않는다. 새 MCP는 반복 작업·편집 세션이 실제로 필요할 때만 검토한다.
