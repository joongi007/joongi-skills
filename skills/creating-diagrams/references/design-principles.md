# 형식과 독립적인 다이어그램 디자인

Mermaid·Excalidraw·SVG·HTML로 다이어그램을 만들거나 변환할 때 먼저 읽는다.
[diagram-design](https://github.com/cathrynlavery/diagram-design)의 설명 중심 디자인·단순화·시각 검수 접근을
참고해 작성한 공통 지침이다. 원본 전체를 설치하거나 그 스타일·검사 스크립트를 그대로 강제하지 않는다.

## 내용과 표현

- 독자가 그림에서 알아야 할 핵심을 한 문장으로 정한다. 목록·표·짧은 문장이 더 명확하면 그 형식을 선택한다.
- 먼저 의미를 고른다. 구성요소·경계는 구조도, 시간 순서는 시퀀스, 상태와 조건은 상태도처럼
  설명할 관계에 맞게 유형을 정한 뒤 제작 도구를 선택한다. 기존 원본이나 지정 형식이 있으면 존중한다.
- 도형·그룹·화살표는 실제 구성요소·책임·데이터·전이를 나타낸다. 보기 좋은 배치를 위해 없는 요소를 만들거나
  중요한 분기·실패·병렬성을 생략하지 않는다. 단순화한 경계와 가정은 캡션에 남긴다.
- 각 요소가 서로 다른 정보를 담는지 확인한다. 중복 설명·장식·의미 없는 선을 덜고, 필수 정보를 유지한 채
  복잡하면 개요와 상세로 나눈다. 노드 수 제한 때문에 실제 구조를 바꾸지 않는다.

## 배치와 시각적 위계

- 기존 프로젝트의 토큰·폰트·배경을 우선한다. 필요한 경우 `applying-design-systems`의 선택 절차를 사용한다.
  원본의 특정 팔레트·폰트·그림자 금지·고정 노드 수는 공통 요구사항으로 가져오지 않는다.
- 주요 읽는 방향을 정한다. 흐름도는 시작·분기·종료를, 구조도는 책임 경계와 핵심 관계를 따라갈 수 있어야 한다.
  비교 그림은 같은 축·용어·배율을 쓴다.
- 핵심만 강조하고 나머지는 배경 정보로 둔다. 같은 역할은 같은 표현으로, 다른 계층·책임은 그룹·크기·레이블로 구분한다.
- 정렬·간격·내부 여백을 일관되게 두고 텍스트가 들어갈 공간을 확보한다.
  서로 다른 계층·역할을 같은 크기·표현으로 평평하게 만들지 않는다.
- 색만으로 상태나 의미를 구분하지 않는다. 레이블·선 형태·범례를 함께 쓰며 범례는 실제 기호와 대응시킨다.

## 연결선과 텍스트

- 화살표 끝이 올바른 대상·경계에 닿는지 확인한다. 선의 교차·겹침·불필요한 꺾임을 줄인다.
- 연결선의 방향·실선/점선·레이블이 실제 흐름과 맞아야 한다. 데이터와 제어, 동기와 비동기를 같은 표기로 혼동시키지 않는다.
- 선이 레이블을 관통하지 않도록 위치·배경 여백·렌더러 설정을 조정한다. 화살표를 따라 세로로 돌린 긴 문장 대신
  짧은 레이블이나 별도 주석을 사용한다. 설명과 조건을 줄일 때 의미를 보존한다.
- 제목·본문·보조 설명의 크기 차이를 정하고 최종 표시 크기에서 읽는다. 과도한 축소 대신 분할·레이아웃 조정을 검토한다.

## 렌더·삽입 완료 기준

1. 사용한 원본을 실제 렌더러·편집기로 열어 구문, scene binding, 누락된 폰트·이미지를 확인한다.
2. 목표 폭·배경·배율로 렌더한 파일을 열어 글자 잘림·겹침·선 연결·한글·대비를 확인한다.
   구문 통과나 원본 저장만으로 시각 검수가 끝났다고 하지 않는다.
3. [형식별 지침](diagrams.md)에 따라 문서·앱에 삽입하고 실제 본문 폭에서 다시 확인한다.
   이미지에는 핵심 관계를 설명하는 대체 텍스트·캡션을 제공한다. 독립 SVG는 의미 있는 title/desc도 둔다.
4. 편집 가능한 원본과 확인한 렌더 산출물 또는 재현 가능한 빌드 경로를 전달한다.
   의미·레이블·레이아웃이 바뀌면 다시 렌더해 삽입 이미지와 원본을 맞춘다.
