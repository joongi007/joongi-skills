# 자연스러운 한국어

평소에 쓰는 자연스러운 한국어로, 읽는 사람이 뜻을 바로 이해하도록 쓴다.
한국어라는 이유로 모든 단어를 번역하지 않는다. “SNS에 팔로우 버튼이 있어요”면 충분하다.

## 사용 절차

1. 누구에게 쓰는 글인지, 답변·기술 문서·제품 문구 중 무엇인지 확인한다.
   문맥에서 알 수 있으면 바로 작성한다.
2. 프로젝트 용어와 사용자가 지정한 문체를 우선한다. 별도 요청이 없는 대화는 자연스러운 존댓말로 답한다.
3. 표현을 다듬은 뒤 원문과 대조해 뜻과 정보가 보존됐는지 확인한다.
   처음부터 쓰는 글에서도 확인한 사실과 추정을 구분한다.

## 필요한 자료

| 작업 | 읽을 자료 |
|---|---|
| 영어·음역·번역어 선택, 낯선 기술 용어, 검색으로 실제 용례 확인 | `references/terminology.md` |
| 문장 교정, 기술 문서·UI 문구, 적용 예제와 의미 보존 점검 | `references/writing-review.md` |

## 항상 적용하는 기준

- 익숙한 말로 정확히 쓴다. API, MCP, Redis, GitHub는 그대로 쓰고, 버튼·캐시·로그·팔로우처럼 익숙한 표현도 자연스럽게 쓴다. 독자에게 익숙한 한국어가 있으면 굳이 영어로 바꾸지 않는다.
- 영문 UI의 `Follow`를 누르라고 안내한다면 실제 라벨을 유지한다. 기능을 일반적으로 설명할 때는 “팔로우 버튼”이라고 쓸 수 있다.
- 짧게 쓰더라도 조사·서술어·조건을 지워 뜻을 흐리지 않는다. 제목·버튼·표에서는 짧은 명사구를 써도 된다.
- “진행을 수행합니다” 같은 빈말을 구체적인 동작으로 바꾼다. 강조·접속사·목록은 이해에 도움이 될 때 쓴다. 특정 단어와 문장 형식을 일괄 금지하지 않는다.
- 교정할 때 사실, 수치, 단위, 부정, 가능성, 조건, 인과관계, 직접 인용을 보존한다. 문체를 바꾸려고 경험담·근거·확신을 만들어 넣지 않는다.
- 코드·명령어·경로·식별자·로그 이벤트·프로토콜 필드는 프로젝트 표기를 유지한다. 한국어 설명과 구분한다.
- 이미 자연스러운 문장은 유지한다. 사용자가 결과만 요청하면 수정본만 준다. 검토 요청이면 의미에 영향을 주는 변경과 용어 선택 근거를 간단히 설명한다.

## 범위와 근거

한국어 문체를 위한 스킬이다. 외국어 출력 요청이나 문학·브랜드의 지정 문체를 덮어쓰지 않는다.
스킬 설치만으로 모든 클라이언트의 system prompt나 output style이 바뀌지는 않는다.
자동 선택 여부는 클라이언트에 따라 다르므로 명시적으로 `usual-korean`을 지정해서 사용할 수도 있다.

fluent-korean의 명료성, im-not-ai의 의미 보존·번역체 검토 접근과 사용자의 용어 선호를 참고해
새로 작성했다. 조사 기록은 저장소의 `refs/research/2026-11-06-usual-korean.md`에 있다.
