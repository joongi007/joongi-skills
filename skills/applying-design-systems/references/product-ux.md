# 제품 UX 원칙

GTMUX의 디자인 문서에서 여러 제품에 적용할 수 있는 원칙을 추출했다.
특정 앱의 컴포넌트 이름·화면 크기·CLI 기능을 가져오는 지침은 아니다.

## 정보와 동작

- 목록은 이름·현재 상태·짧은 용도와 다음 행동부터 보여준다. 전체 설명·경로·설정·schema는 상세에서 제공한다.
- 사용자가 선택한 항목의 설명을 상세에 보여준다. 동일한 긴 설명을 목록과 상세에 반복하지 않는다.
- 기술 식별자는 검색·복사할 수 있게 유지하고, 사람에게 보여주는 이름과 구분한다.
- 중요한 실행 결과·오류·비용·파괴적 동작의 영향은 접힌 설정 안에 숨기지 않는다.
- 새로고침·필터·비동기 갱신 때문에 선택, 입력, 펼침 상태나 스크롤을 불필요하게 초기화하지 않는다.

## 컨트롤과 상태

- 기존 토큰·컨트롤·간격을 재사용한다. 같은 동작에 서로 다른 모양의 컴포넌트를 새로 만들지 않는다.
- 즉시 반영되는 지속적 on/off 설정은 switch가 적합하다. 여러 항목 선택·동의·실행 시 옵션은 checkbox가 적합할 수 있다.
- label·보조 설명·컨트롤을 일정하게 배치한다. 좁은 화면에서는 순서를 유지하며 세로로 배치한다.
- 시작·실행·종료·실패를 구분한다. 요청 중에는 충돌하는 동작을 막고 관련 없는 탐색은 유지한다.
- 저장 실패·권한 문제·포트 충돌의 원인과 다음 행동을 알린다. 사용자가 선택한 값을 조용히 덮어쓰지 않는다.
- 위험한 동작은 대상과 영향을 실행 버튼 가까이에 설명한다. 확인창을 무조건 추가하지 않는다.

## 환경과 검토

- 프로젝트가 제공하는 테마와 사용자 선택을 존중한다. 테마 전환은 의미와 상태 구분도 유지해야 한다.
- 너비·레이아웃·환경설정은 실제 소유 범위에 저장하고, 저장 실패에도 화면이 복구될 수 있게 한다.
- 키보드 조작, 읽을 수 있는 label, focus, disabled, reduced motion을 확인한다.
- 긴 이름·경로, 빈 상태·실패 상태, 작은 화면에서 실제 작업을 해본다. build 성공만으로 UX 검증을 대신하지 않는다.
