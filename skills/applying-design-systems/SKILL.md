# 디자인 시스템과 UX

기존 디자인 시스템을 먼저 사용한다. 없다면 `github.com/nexu-io/open-design`의
패키지 하나를 선택한다. 라이선스는 Apache-2.0이다. 시각 토큰과 제품의 상호작용을 함께 설계한다.

## 작업 순서

1. 프로젝트 문맥에서 제품·사용자·주요 행동을 파악한다.
2. 기존 토큰과 컴포넌트를 재사용한다. 없다면 카탈로그에서 패키지 하나를 고르고 브랜드를 섞지 않는다.
3. 선택한 패키지의 `tokens.css`만 가져온다. 해결되지 않은 문제가 있을 때만 전체 설계 문서를 읽는다.
4. 의미에 맞는 토큰을 사용하고, 상태 색상과 강조 색상을 구분한다.
5. 키보드·좁은 화면·긴 내용·실패 상태에서 실제 동작을 확인한다.

```text
https://raw.githubusercontent.com/nexu-io/open-design/main/design-systems/<slug>/tokens.css
```

## 기본 원칙

- 이름·현재 상태·다음 행동부터 보여주고, 자세한 지침과 설정은 필요할 때 펼쳐 제공한다.
- 에이전트용 기술 메타데이터는 보존한다. 화면의 짧은 요약으로 원래 설명이나 schema를 대체하지 않는다.
- 기존 컨트롤을 재사용하고, 갱신 중에도 사용자의 선택과 입력을 유지한다.
- 오류와 중요한 동작의 영향은 잘 보이게 둔다. 간결한 화면에도 명확한 label과 focus가 필요하다.
- 토큰은 시각적 값을 제공한다. 레이아웃·컴포넌트·엔지니어링 규칙은 프로젝트 관례에 맞춘다.
- 패키지를 가져오지 못해 값을 직접 정했다면 공식 패키지의 값인 것처럼 설명하지 않는다.
