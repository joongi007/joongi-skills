# 변경 완료 체크리스트 (PLAYBOOK §13)

전부를 매번 실행하는 목록이 아니다. 바뀐 기능·권한·운영 경로에 맞는 항목만 확인한다.
검사할 수 없었던 내용은 미검증으로 남긴다.

## 모든 변경

- [ ] 목적과 사용자가 관찰할 수 있는 수용 조건을 만족하는가.
- [ ] 기존 코드·문서·계약을 확인했고 무관한 기술 교체나 동작 변경을 추가하지 않았는가.
- [ ] 관련 정상·실패·경계 검사를 수행하고 결과·한계를 기록했는가.
- [ ] 설정·예제·지원 범위·운영 문서가 실제 동작과 일치하는가.

## API·인증·데이터 변경

- [ ] 입력·출력·권한·소유권·페이지 및 자원 상한이 검증되는가.
- [ ] 동적 schema·필드·URL·경로·명령 입력에 검증 범위와 제한이 있는가.
- [ ] 이미지 입력은 압축 바이트·실제 치수·누적 프레임·decode 시간·메모리·동시 처리 상한이 있는가.
- [ ] parser·SQL·shell·template에서 데이터가 코드로 해석되지 않는가.
- [ ] 토큰·세션·키의 발급·갱신·폐기·재인증과 동시 요청을 검증했는가.
- [ ] 브라우저 인증의 XSS·CSRF·쿠키·저장 수명·로그인 종료 동작을 검토했는가.
- [ ] 쓰기 재시도·결제·재고·중복 요청의 원자성·멱등성·부분 실패를 검증했는가.
- [ ] 비밀·개인정보가 응답·로그·trace·cache·진단 자료에 불필요하게 남지 않는가.

세부: `web-security.md`, 선택한 JWT 계약은 `auth-jwt.md`, UI는 `frontend.md`.

## UI·비동기 변경

- [ ] 로딩·빈 상태·오류·재시도·취소가 구분되고 키보드·작은 화면에서 사용할 수 있는가.
- [ ] 늦은 응답이 새 선택·입력·프로젝트 범위를 덮어쓰지 않는가.
- [ ] 서버 상태·편집 상태·cache 수명과 구독·이벤트·태스크 정리가 명확한가.
- [ ] blocking I/O·CPU 작업·동시성·큐·외부 호출에 적절한 실행기와 상한이 있는가.
- [ ] 취소·timeout 후 계속 실행할 작업만 보호하며 외부 부작용을 성공으로 오인하지 않는가.

세부: `frontend.md`, `concurrency.md`, `async-patterns.md`.

## 배포·인프라·운영 변경

- [ ] 버전·라이선스·이미지·설정과 마이그레이션·rollback을 검증했는가.
- [ ] 최소 권한·노출된 관리 경로·네트워크·공급망·비밀 관리가 적절한가.
- [ ] 실패·침해 시 신호·알림 수신자·초기 제한·자격증명 폐기·복구 절차가 있는가.
- [ ] 자동 조치의 오탐·영향 범위·해제·실패·감사 로그를 검증했는가.
- [ ] 백업이 실제 복원되고 RPO/RTO·복제 지연·quorum·장애 전환이 요구에 맞는가.
- [ ] Actuator·JMX·attach·core/heap dump와 요청 컨텍스트를 해당 스택에서 점검했는가.

세부: `security-ops.md`, `incident-response.md`, `infrastructure-ha.md`,
`database-recovery.md`, `kubernetes-helm.md`, `java-actuator.md`, `memory-secrets.md`.

## 선택한 스택·작업 방식

- Python/FastAPI/SQLAlchemy: `python-api.md`의 트랜잭션·Repository 예시를 기존 계약에 맞춰 확인한다.
- DB를 공유하는 API·worker: `architecture.md`의 소유권·배포·마이그레이션 호환성을 기록한다.
- 로그·설정·도구: `logging.md`, `config-secrets.md`, `lint-naming.md`의 해당 언어 예시만 적용한다.
- 핵심 로직: `documentation-testing.md`를 따라 불변식·mutation 누락을 확인한다. 수치만 목표로 삼지 않는다.
- 병렬 작업: 계약·소유 파일·독립 검증·통합 결과를 확인한다. 단일 작업에는 불필요한 분할을 강제하지 않는다.
