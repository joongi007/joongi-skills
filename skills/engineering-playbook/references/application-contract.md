# 적용 계약과 판단 기록

이 문서는 플레이북을 읽는 사람·에이전트가 같은 범위·용어·완료 기준으로 작업하도록 하는 공통 기준이다.
모델의 배경지식이나 판단 결과가 완전히 같아진다고 보장하지 않는다. 판단에 필요한 입력과 증거를 맞춘다.

## 지침의 성격과 우선순위

| 구분 | 의미 | 적용 방법 |
|---|---|---|
| 공통 원칙 | 권한 경계·자원 상한·데이터 무결성·검증 등 목표 | 작업과 관련된 항목을 기본 점검 |
| 표준·제품 계약 | RFC의 요구, 엔진 동작, 특정 버전의 API | 출처·버전·적용 조건을 확인 |
| 프로젝트 결정 | 저장소의 API·도메인 용어·ADR·운영 정책 | 기존 결정을 확인하고 변경 영향을 관리 |
| 선택형 예시 | 폴더명·라이브러리·설정값·사용자 정의 claim | 필요한 경우만 채택; 표준이나 실제 기본값으로 간주하지 않기 |

사용자 지시와 저장소의 구체적인 계약을 먼저 확인한다. 공통 가이드로 기존 계약을 묵시적으로 바꾸지 않는다.
동시에 취약하거나 목적을 충족하지 못하는 계약을 관례라는 이유로 안전하다고 기록하지 않는다.
충돌하면 적용 범위·출처·피해·변경 대안을 제시하고, 권한 안의 수정 또는 필요한 결정·미해결 위험을 남긴다.
파일의 최신 수정일만으로 더 높은 우선순위를 부여하지 않는다.

이 플레이북의 “요구한다·금지한다”는 해당 절의 전제 안에서 해석한다. 예제의 도구·수치·필드명에는
자동 적용하지 않는다. 규범적 MUST/SHOULD/MAY는 인용한 표준이 그 뜻으로 정의했을 때만 사용한다.
보안 목표는 유지하면서 구현 수단은 스택·위험·운영 여건으로 선택한다.

## 작업 시작과 완료의 공통 입력

1. 목적·수용 조건·대상 버전/커밋·변경 가능한 범위를 확인한다.
2. 실행 환경·언어·배포 단위·데이터 원천·사용자/tenant·신뢰 경계를 필요한 만큼 적는다.
3. 관련 주제의 기준 문서만 선택하고, 불명확한 사항은 확인된 사실·가정·미검증으로 나눈다.
4. 선택 이유·대안·실패 비용을 남긴다. 짧은 수정은 PR 설명으로 충분하며 모든 작업에 ADR을 만들지 않는다.
5. 정상뿐 아니라 관련 실패·권한·동시성·복구 경로를 검증한다. 문구 수정에는 무관한 운영 검사를 강제하지 않는다.
6. 결과·증거·남은 위험·문서 변경을 보고한다. 미실행은 통과가 아니다. 전용 보안 검수 범위는 아래 기준 문서를 따른다.

형식이 없다면 다음을 사용한다. 기존 이슈·PR·ADR 양식이 있으면 그 양식을 유지한다.

```text
목적 / 수용 조건 / 대상 커밋·버전:
범위 / 환경 / 신뢰·데이터 경계:
적용한 기준 문서 / 프로젝트 결정 / 가정:
선택 / 이유 / 대안 / 실패·복구 비용:
검증 명령·조건 / 관찰 결과 / 증거 위치:
미검증·남은 위험 / 후속 조치·담당자:
```

## 충돌·중복을 검토하는 방법

같은 개념을 다루는 문장을 전제·행위·보장·실패 정책으로 나눠 대조한다.
“메이저 태그 선택”과 “동일 이미지 재현”, “요청 취소”와 “실행 중단”, “로그아웃”과 “Access Token 철회”처럼
관련은 있지만 보장이 다른 개념을 합치지 않는다. 예제값은 실제 기본값과 구분한다.
링크·라우팅·번들 검사를 자동화하고 의미 충돌은 독립적인 실패 시나리오로 확인한다.
상세 계약을 링크로 옮겼을 때에도 독자가 어떤 주제를 먼저 읽을지 알 수 있게 한다.
